# 币安 USDT 合约只读监控

程序只监控状态为TRADING、报价和保证金币种均为USDT的永续合约，不监控交割合约。程序读取公开行情，计算 EMA12、EMA50、EMA200 和前15根量价比较，普通六项条件全部满足，或量比与实体扩张同时满足特别条件，即记录信号；符合既有事件类型和120秒时效规则时发出提醒。四个周期独立运行：15分钟、1小时、4小时、日线。没有交易、账户或资金接口，也不需要交易 API 密钥。

## 本机启动

在本文件所在目录打开 PowerShell。本次交付的本地目录已准备好 Python 依赖和历史数据库。重新解压代码包时先执行安装。

启动及安装脚本使用带BOM的UTF-8编码，兼容Windows PowerShell 5.1。编辑这些脚本时请保留此编码，避免中文被误读为乱码而导致语法错误。

启动后控制台会立即显示程序目录和初始化提示，历史检查结束后显示订阅状态；运行期间每60秒显示一次简短状态。控制台状态输出不触发Excel刷新。旧进程不会热加载这些提示，重新启动后生效；没有触发提醒并不表示程序停止。

```powershell
# 新安装时执行一次；本机已准备好的目录无需重复
.\setup.ps1

# 初始化数据库（重复执行安全）
.\start-local.ps1 -Command init

# 持续运行，默认仅控制台和本地事件日志提醒
.\start-local.ps1 -Command run

# 在另一个窗口查看状态、请求优雅停止
.\start-local.ps1 -Command status
.\start-local.ps1 -Command stop

# 只补齐历史，不持续订阅
.\start-local.ps1 -Command bootstrap

# 停机后重新生成四份 Excel
.\start-local.ps1 -Command export

# 短时验证：初始化/补数结束后再运行300秒
.\start-local.ps1 -Command run -Seconds 300
```

同一个数据目录仅允许一个写入实例。`export` 命令是停机后的手动导出；持续监控时不需要另开导出进程。自动刷新只发生在启动和对应周期收盘后：

| 文件周期 | 自动刷新时点（北京时间） | 正常连续运行频率，不含启动那一次 |
| --- | --- | --- |
| 15分钟 | 每小时00、15、30、45分收盘后 | 每小时4次 |
| 1小时 | 每小时整点收盘后 | 每天24次 |
| 4小时 | 每天00、04、08、12、16、20点收盘后 | 每天6次 |
| 日线 | 每天08:00收盘后 | 每天1次 |

启动时四个周期各生成一次“启动快照（历史恢复中）”，显示当时数据库已保存的记录，历史恢复和行情订阅继续进行。每个周期随后独立等待本周期收盘数据完成判断。收盘数据汇齐最多等待30秒；仍未到齐时发布明确标注“不完整”的报表，列出已处理数量/应处理数量，并在当前状态页标注 `CLOSE_NOT_PROCESSED`。补数完成后刷新同一收盘批次，取该根K线已保存的判断，保留原收盘时间。未完成批次在导出前持久化，重启后继续检查。四个周期共享一个流式导出工作进程，避免多个压缩任务叠加内存。

文件生成和落盘还需时间，“快照时间”是读取数据库的时间，不是收盘时间或保存完成时间。顶部单独列出本次对应的收盘边界及覆盖数量；`导出清单.json` 的 `by_interval` 保存每个周期的快照时间、完成时间和文件位置。异常休眠或长时间导出积压时，恢复后合并到最新收盘边界，并记录 `EXPORT_BOUNDARIES_SKIPPED`，不会把最新数据标成旧边界。

`config.json` 中保留 `export_seconds` 以兼容既有策略版本，但不再用于定时刷新。双击 Excel 查看时可能锁住文件，程序会另存时间戳快照并标记待替换，下一次约定刷新时重试；已打开的 Excel 不会自动加载磁盘上的新版本，需关闭后重新打开。

启动 `run` 并保持监控进程、机器和网络可用，才会继续监控。代码和配置修改不会自动加载到旧进程；更新后需先优雅停止，再重新启动，新放量规则和Excel归档规则才生效。

## 收盘采集窗口

15分钟在收盘前2分钟、1小时在收盘前5分钟、4小时在收盘前10分钟、日线在收盘前15分钟开启实时订阅。同一收盘时刻涉及多个周期时，所有相关周期统一采用最长提前量：例如北京时间08:00四周期同时收盘，统一07:45开启；04:00的15分钟、1小时和4小时统一03:50开启；普通整点的15分钟和1小时统一提前5分钟。

仍只处理已收盘K线，提前采集不提前判断或提醒。该收盘批次的数据处理完成后关闭对应窗口；未收齐的数据单独补取。非采集窗口显示等待下一窗口，零条行情连接属于正常待机。启动初始化、缺口补数、交易对清单更新和Excel原有刷新/归档规则保留。

## 配置与提醒

编辑 `config.json` 后重启。当前有普通和特别两条触发路径。普通路径仍要求累计至少200根K线，以下六项必须同时满足：

1. 目标K线为阳线，且收盘价严格高于此前15根K线的最高价。
2. 收盘价分别严格高于EMA12、EMA50、EMA200；不要求三条EMA多头排列，也不要求EMA12上升。
3. 1小时、4小时、日线成交量 `V >= 2.5 × V15_mean`；15分钟成交量 `V >= 4 × V15_mean`。四个周期均同时要求 `V > V15_max`；均量倍数包含等号，与最大量比较不包含等号。
4. 相对实体 `abs(C/O-1)` 至少为此前15根平均相对实体的2倍。
5. 开收盘涨幅 `C/O-1` 严格高于此前15根的最大开收盘涨幅。
6. 实体占比至少0.59，上影占比至多0.41。令实体 `B=abs(C-O)`、上影 `U=H-max(O,C)`，实体占比为 `B/(B+U)`，上影占比为 `U/(B+U)`，不计下影线；普通路径分母为零时形态指标不可用且不触发。实体占比≥59%、上影占比≤41%，两者之和为100%，边界包含等号；特别路径不受这两项限制。

特别路径适用于15分钟、1小时、4小时、日线：`V >= 12 × V15_mean` 且 `relative_body / B15_mean >= 6`。相对实体为 `abs(C/O-1)`，`B15_mean` 为此前15根相对实体均值。两项均包含等号，必须同时满足；此前15根均量与平均相对实体必须大于零。特别路径不要求阳线、突破、EMA、超过前15根最大成交量、涨幅扩张或影线比例。已有目标K线及此前15根完整已收盘K线即可，不受200根EMA预热门槛限制；行情合法性、连续性、永续合约范围和提醒时效仍保留。两条路径同时满足时只记录一条信号。`NOT_READY` 仍表示EMA预热不足，不表示特别条件不可用；此时特别信号会同时显示“特别条件”和真实累计K线数。

“此前15根”不包含目标K线，按各自周期计算：15分钟取此前15根15分钟K线，1小时取此前15根1小时K线，4小时取此前15根4小时K线，日线取此前15根日K线。各周期量比阈值、相对实体倍数2、实体占比0.59和上影占比0.41保存在 `config.json`。触发倍数以 `volume_multiple_by_interval` 的周期映射为准，红字倍数以 `volume_highlight_multiple_by_interval` 为准；映射优先于保留的单值 `volume_multiple`，仅修改单值不会覆盖周期映射。新判断记录保存实际使用的阈值。没有多周期共振要求、冷却期或额外EMA斜率条件。

1小时、4小时、日线若 `V >= 4 × V15_mean`，15分钟若 `V >= 5 × V15_mean`，且同时满足 `V > V15_max`，Excel“监控概览”和“触发记录”中对应记录整行使用红色字体。标红仅表示满足这一放量条件；监控概览中的红色行不一定满足普通或特别触发条件；特别条件触发的记录（包括普通条件与特别条件同时满足）整行使用蓝色字体，蓝字优先于放量红字，且不要求超过前15根最大成交量。触发记录、监控概览均按已保存的触发依据着色，不将旧策略记录按当前倍数追溯标蓝。

配置内容和公式版本生成策略哈希，本次公式版本为v4，历史v1/v2/v3信号保留原指标、原阈值、原红字规则和旧版本，不按新倍数重算。恢复时继续使用已保存的EMA种子与增量状态，不重置为新的1500根滑动种子；旧20根状态从后续新K线判断起使用最近15根作比较，不倒带重算已有信号。运行时覆盖 `MONITOR_NODE` 也纳入配置版本，因此请固定启动方式。

默认仅分析初始化阶段的最新K线；设置 `historical_analysis=true` 后，首次初始化会计算全部可判断历史K线。现有数据库不会自动倒带重算旧记录。需要完整历史研究时使用新的 `data_dir`，避免改变正在运行的监控状态。`historical_summary=true` 会在初始化结束后向本地日志和控制台输出一条去重历史汇总，默认关闭。

提醒文件是 `runtime/events.jsonl`，详细通知状态持久化在数据库 `outbox` 和 `deliveries` 表。`HISTORICAL` 不进入实时通知；`RECOVERED` 保留补数来源；发现时间晚于收盘边界120秒的信号为 `EXPIRED`，仍保存但不即时通知。队列等待也计入发现延迟。

只有明确授权并配置后，才启用外部 HTTPS webhook：将 `webhook_authorized` 设为 `true`，并在 `MONITOR_WEBHOOK_URL` 环境变量中设置接收地址。URL不得写进配置或日志。代码不会替你添加联系人、群组或机器人。发送使用 `Idempotency-Key: signal_id`；接收端应按该ID去重。网络故障或进程在发送成功后、写入送达状态前退出时，外部渠道仍可能重复投递，不能保证严格恰好一次。

## 输出与数据

- `excel/`：四个周期各一份当前期间的主工作簿，依次为触发记录、监控概览、历史K线对照、数据状态与异常、参数与说明、近期异常。默认打开“触发记录”；六张表的表头和数据区域使用细框线，只冻结表头，不冻结列。“数据状态与异常”保留全部当前交易对状态，历史异常另列于“近期异常”。
- `excel/历史币安USDT合约监控/`：已结束期间的Excel及首次启用归档时保存的旧累计Excel；历史数据库记录仍全部保留。
- `runtime/monitor.sqlite3`：全部已采集原始K线、增量状态、判断、信号、配置版本、通知发件箱及异常记录。
- `runtime/health.json`：运行状态、每周期就绪数量、订阅连接、消息计数、补数积压、延迟和最近导出状态。
- `runtime/monitor.log`：轮转结构化日志。`runtime/events.jsonl`：轮转提醒日志。日志轮转不删除数据库中的信号和通知历史。
- `runtime/export-cache/`：可重新生成的导出缓存和检查记录。数据库是事实来源。

Excel中的价格和统计是引擎已计算并保存的数值快照，不是可编辑的策略计算器。价格按精度显示；UTC毫秒和北京时间同时保留。每次周期导出由一次数据库读事务保证内部一致，四个周期的快照时间独立。日线使用交易所UTC日线，北京08:00结束。空白表示不可用，不能按0理解。

“触发记录”的“触发K线收盘时间 北京”标明哪一根K线触发，例如15分钟的15:30表示15:15至15:30这根K线。“触发发现时间 北京”是程序处理并发现该信号的时间，可能晚于收盘时间，保留原始UTC毫秒便于核对。“触发依据”区分普通条件、特别条件及两者同时满足，普通六项检查保留真实结果；历史单路径信号显示普通条件，不以新规则重算。`signal_id` 和“策略版本”仍位于最后两列。

统计列使用“比较均量”“比较最大量”等中性标题，每行“比较窗口根数”区分新策略的15根与旧策略的20根。“历史K线对照”按该条信号实际使用的窗口展示。旧信号保持当时的指标、触发判定和策略版本，不按新规则重算或标红。

Excel按以下期间独立换新和归档，所有时间均为UTC+8（北京时间）；换新在启动或对应周期收盘后的约定刷新中执行，不增加其他刷新时点。

| 文件周期 | 当前文件保存范围 | 换新与归档边界 |
| --- | --- | --- |
| 15分钟 | 当天08:00至次日08:00 | 每天08:00 |
| 1小时 | 本周一08:00至下周一08:00 | 每周一08:00 |
| 4小时 | 起始周周一08:00至两周后周一08:00 | 以2026年10月19日08:00为起点，下一次为2026年11月2日08:00，之后每两周一次 |
| 日线 | 本月1日08:00至下月1日08:00 | 每月1日08:00 |

触发记录按程序保存的发现时间 `discovered` 归属期间，采用 `[开始时间, 结束时间)`：恰好在结束边界发现的提醒计入下一期。K线收盘时间仍单独保留供验证，因此晚到或补数信号的收盘时间可能早于其所属提醒期间。

首次启用期间归档时，将原有累计Excel移入 `excel/历史币安USDT合约监控/`，再生成当前期间文件。此后换期将上一期文件归档到同一目录。若Excel正被打开而无法移动或替换，保留原文件并另存快照，下一次约定刷新重试；不会因归档失败删除原文件。停机错过换期边界时，下次启动会恢复归档处理，不需要手工删除文件。

信号及历史K线对照接近容量上限时在各自归档期间内分卷，容量按各条信号实际的15根或20根明细累计；主文件保留最新一卷，同期其他卷另存，换期一并归档。近期异常限定最近24小时、最多2000组，按交易对、周期、异常类型及说明聚合，列出首次时间、最近时间、次数，并注明是否截断。完整原始异常在数据库保留，按编号增量保存到历史目录的“异常历史”压缩 JSONL 文件，批次清单含行数、范围与校验值。Excel归档不删除任何原始记录，包括EXPIRED。监控概览始终列出完整当前清单，数量随上市/下架更新，不固定为524个。

历史Excel继续保持日、周、双周、月的原划分。按归属期结束时间计龄，30天内留在原历史目录，31至90天移动到“月归档/年-月”，超过90天移动到“年归档/年”。仅整理文件位置，不合并、不删除内容。

## 有界导出与健康状态

导出只读取当前归属期和确实变更的历史期。归属时间仍采用触发发现时间，按UTC+8的08:00分界。SQLite复合索引和游标分页默认每批500条；历史期版本未变更即跳过。原始K线与历史策略判断不重新计算。磁盘缓存保存已准备行的版本、内容哈希和格式状态，新增信号追加到已有行序末尾。

XLSX通过Archiver流式压缩写入，缓存放在磁盘，不在内存累积整本工作簿。一个工作块最多5000行或50MiB编码数据，输出使用背压控制；不需要把所有块重新读入内存合并。XLSX是压缩包，更新时仍需流式写出新的文件；复用缓存避免重新计算、格式化未变更行，不代表能原地追加ZIP内容。

`export-settings.json`单独控制导出预算，避免改变原策略版本：默认工作进程RSS上限512MiB、Node堆上限256MiB、每次导出超时180秒。操作系统监测进程峰值并在超预算时终止。OOM立即记录本地告警，暂停同一版本的失败任务；一般失败连续3次也暂停。修复原因后，停机执行 `.\start-local.ps1 -Command reset-export` 再启动。代码版本变化可重新尝试。告警保存至 `runtime/export-alerts.jsonl`，不向未授权的外部渠道发消息。

`runtime/health.json`中`export_health.by_interval`分别列出最后成功写入时间、报表对应收盘、处理覆盖数、最近完整收盘、失败原因、耗时、峰值内存和暂停状态。归档健康单独放在`history_maintenance`，归档故障不会把已经成功写入的主报表改称失败。首次修复全量历史导出可在停机后运行 `.\start-local.ps1 -Command export -Backfill`。

SQLite备份使用`python -m monitor.maintenance backup --source <数据库> --destination <新备份>`，固定读事务后调用在线备份API并验证。不能直接复制运行中的主数据库文件。`vacuum --data-dir <runtime目录> --backup-dir <备份目录>`只在停机、获得实例锁并完成新一致性备份后执行；不在收盘路径自动运行，也不删除任何历史。定期维护应安排在停机窗口。

## 架构与恢复

`core.py` 管理指标、信号和SQLite事务；`transport.py` 只允许三个公共GET端点并订阅公开K线；`service.py` 管理清单、预热、顺序处理与补数；`notifications.py` 分发持久化发件箱；`export.py` 和 `excel_builder.mjs` 在独立工作线程/子进程中导出。市场队列容量10000，补数去重队列容量10000，每连接默认200个订阅；每个交易对和周期有独立锁。信号队列使用持久化表承接；四个周期独立调度和导出缓存，同一周期串行写入，导出清单按周期合并。停机等待进行中的导出结束。

REST权重使用滚动窗口预算，且根据exchangeInfo返回的分钟上限保留至少25%余量。初始1500根请求权重10，增量最多499根权重2；有界并发、429/418退避、服务器时间校准。WebSocket自动响应ping，断线重连补数，连接存活23小时后主动轮换。后台每10秒检查遗漏收盘，清单默认每15分钟刷新。空清单或刷新失败保留上次有效清单并标记过期。

发现缺口、OHLC异常或冲突重复时，停止受影响的交易对/周期判断，其他任务继续。有效但不连续的源K线仍可保存供排查，不虚构缺失K线。新上市不足200根为NOT_READY；200至1499根为SHORT_WARMUP，允许触发；1500根起为READY。数据错误和预热状态分别记录，不能把READY等同于网络实时可用。

重启直接运行 `run`，会恢复EMA状态并从最后一根后面补齐。备份前使用 `stop` 并等待状态 `running=false`，再复制整个 `runtime` 目录；不要在运行时仅复制主SQLite文件而漏掉WAL。恢复时把备份放回配置指定数据目录，保持相同策略配置。不要删除种子或手工修改状态。

数据库结构在 `monitor/core.py` 的 `SCHEMA`，初始版本1。启动幂等创建缺少的表；本版本不提供破坏性迁移。未来结构升级应先停机备份再迁移。SQLite使用WAL、FULL同步和唯一约束；信号与发件箱在同一事务提交。
