
你是一名资深量化数据系统工程师。请将以下需求实现为生产级币安合约监控程序。

这是监控和提醒系统，不是交易系统。请交付完整可运行代码、配置示例、自动化测试、部署文档及验证报告，不要只给设计方案。

优先检查并融入现有项目。没有现有项目时默认使用 Python，依赖版本必须明确。涉及币安接口、订阅限制和限流规则时，查阅最新官方文档，不猜测参数或沿用未经核实的旧接口。

一、系统边界：只监控，不交易

程序只能：

- 读取公开交易规则和行情。
    
- 计算指标。
    
- 判断监控条件。
    
- 保存数据、生成Excel。
    
- 向已配置且获授权的渠道发送提醒。
    

禁止实现或调用以下功能：

- 下单、撤单、止盈止损订单。
    
- 修改杠杆、保证金或持仓模式。
    
- 转账、划转或资金操作。
    
- 查询账户余额、用户订单及持仓。
    

公开行情无需交易权限。默认不要求用户提供交易API密钥，不引入具有交易能力的执行模块。

原策略中的买入价、止损价、止盈价、仓位计算和订单管理全部删除。本程序只报告“监控条件触发”，不把提醒描述成实际成交或保证盈利的买入建议。

二、监控范围

监控币安合约市场全部符合以下条件的交易对：

- USDⓈ-M合约产品。
    
- quoteAsset为USDT。
    
- marginAsset为USDT。
    
- 交易状态为TRADING。
    
- 提供目标周期的正常交易价格K线。
    

包括符合条件的永续和交割合约，分别保留contractType；不要仅凭交易对名称以USDT结尾来筛选。

通过交易所exchangeInfo动态发现交易对，禁止维护一份固定名单冒充全市场。

默认每15分钟刷新交易对清单：

- 新上市标的：自动加入，补齐历史并检查指标准备状态。
    
- 停止交易或下架标的：停止生成新提醒，保留历史。
    
- 交割合约：按实际状态和交割信息管理。
    
- 接口暂时不可用时，保留最后一次有效名单并标记过期，不得把空响应视为全部下架。
    

任何主动排除的标的都必须记录原因。

三、四个周期独立监控

监控周期：

- 15分钟：15m。
    
- 1小时：1h。
    
- 4小时：4h。
    
- 日线：1d。
    

每个交易对、每个周期独立维护：

- 历史K线。
    
- EMA12、EMA50、EMA200。
    
- 前20根比较窗口。
    
- 数据准备状态。
    
- 信号状态和提醒去重状态。
    

不得要求多个周期同时满足条件，除非以后明确新增这种功能。

“前20根”的含义：

- 15分钟：此前20根15分钟K线，覆盖5小时。
    
- 1小时：此前20根1小时K线，覆盖20小时。
    
- 4小时：此前20根4小时K线，覆盖80小时。
    
- 日线：此前20根日K线，覆盖20个交易所日周期。
    

严禁把四个周期全部错误地按“过去20小时”处理。

四、数据来源与时间

研究和接口核验优先使用用户指定的币安MCP。若MCP不能满足全市场实时订阅需求，生产程序使用币安官方公开REST及WebSocket接口，并说明两者的分工。

使用真实合约交易价格K线，不以标记价格K线、指数K线或现货K线替代。

时间要求：

- 内部统一使用UTC时间戳。
    
- Excel和提醒默认显示北京时间Asia/Shanghai，同时保留UTC毫秒字段。
    
- K线唯一键为交易对、周期、开盘时间。
    
- 只有交易所确认收盘后，才能计算正式信号和发送提醒。
    
- 正在形成的K线可以用于界面展示，但不得触发正式提醒。
    
- 日线使用币安原生UTC日线，北京时间08:00结束，不自行改成北京时间00:00结束。
    
- 明确区分开盘时间、API收盘时间、周期结束边界和提醒发出时间。
    

例如：

北京时间08:00开盘的1小时K线，09:00收盘确认后才能判断完整信号。

检查重复、缺失、乱序、异常OHLC、过期数据及系统时钟偏差。数据不完整时停止对应交易对和周期的信号判断，其他正常任务继续运行。

五、历史预热与EMA计算

只计算EMA12、EMA50、EMA200，不增加其他均线条件。

公式：

EMA_N[t] = α × C[t] + (1−α) × EMA_N[t−1]  
α = 2 / (N+1)

采用首根初始化数据的收盘价作为种子，并明确记录初始化起点。

启动时每个交易对和周期优先加载1500根已收盘K线：

- 上市历史不足1500根时，使用可获得的全部连续完整历史。
    
- 少于200根时标记NOT_READY，不生成正式信号。
    
- 达到200根但不足1500根时允许判断，标记SHORT_WARMUP并保存实际预热长度。
    
- 不补造上市前数据，不用其他周期数据替代。
    
- 日线不足200根的标的继续跟踪和积累，不得从监控清单中静默删除。
    

维护增量计算状态。重启后应从持久化状态恢复，或使用相同初始化起点重建，保证结果可复现。

六、指标定义

对于目标已收盘K线t：

O、H、L、C：开、高、低、收。  
V：基础币成交量。  
QuoteVolume：USDT成交额。

不同交易对的基础币数量不能直接横向比较。量比使用该交易对自身历史成交量计算。

前20根窗口：

W = [t−20, …, t−1]

必须排除目标K线t。

计算：

body = C − O  
abs_body = abs(C − O)  
relative_body = abs(C / O − 1)

bar_return = C / O − 1  
close_return = C / C[t−1] − 1

V20_mean = mean(V[i], i∈W)  
V20_median = median(V[i], i∈W)  
V20_max = max(V[i], i∈W)

B20_mean = mean(abs(C[i] / O[i] − 1), i∈W)  
G20_max = max(C[i] / O[i] − 1, i∈W)  
H20 = max(H[i], i∈W)

volume_ratio = V / V20_mean  
relative_body_ratio = relative_body / B20_mean

body_share = abs(C−O) / (H−L)  
upper_wick_share = (H−max(O,C)) / (H−L)

同时保存：

- 目标绝对实体与前20根绝对实体均值、中位数、最大值的比较。
    
- 前20根中阳线数量及阳线实体均值。
    
- 目标开收盘涨幅与此前20根涨幅的比较。
    
- 目标加前20根共21根中的成交量、实体及涨幅排名。
    

禁止把正负实体相加抵消后称为“平均实体大小”。

零分母、无效价格、数据缺失或指标未准备好时，结果标记不可用，不产生信号。

七、正式提醒条件

对每个交易对、每个周期，在目标K线收盘后判断。以下六项必须全部满足：

1. 阳线突破：
    
    C > O  
    C > H20
    
2. 必选EMA多头排列：
    
    C > EMA12[t] > EMA50[t] > EMA200[t]
    
    并且：
    
    EMA12[t] > EMA12[t−1]
    
    EMA12 > EMA50 > EMA200必须严格成立。  
    均线相等或排列错误时，不触发。  
    不要求EMA50和EMA200斜率同时向上，不得擅自添加条件。
    
3. 放量：
    
    V >= 2 × V20_mean  
    V > V20_max
    
4. 实体扩张：
    
    relative_body >= 2 × B20_mean
    
5. 涨幅扩张：
    
    bar_return > G20_max
    
6. 阳线形态：
    
    body_share >= 0.60  
    upper_wick_share <= 0.30
    

所有周期默认使用同一套阈值，但计算窗口及指标完全独立。

阈值可以通过配置调整，默认值必须保持上述设定。每次配置变化生成新的策略版本号；历史信号保留原版本，不得被新参数悄悄覆盖。

每次判断记录：

- 六项条件的实际值。
    
- 对应阈值。
    
- 通过或未通过。
    
- 数据状态。
    
- 最终结果。
    

参数不是经过验证的最优值；提醒只表示满足这组量价条件，不代表未来必然上涨。

八、提醒规则

正式提醒事件以以下字段作为幂等键：

strategy_version + symbol + interval + kline_open_time

规则：

- 同一根K线重复推送、重复补数或重启重算，只产生一个逻辑提醒事件。
    
- 不同周期分别提醒，不相互抑制。
    
- 同一标的后续另一根K线再次满足条件，可以产生新提醒。
    
- 不增加未经要求的数小时冷却期。
    
- 可以把短时间内多个提醒合并发送，但不得遗漏任何事件。
    

历史与实时分开：

- 初始化历史补数不发送实时提醒。
    
- 可计算历史触发并保存Excel，但标记HISTORICAL。
    
- 断线补数发现的信号，标记RECOVERED。
    
- 默认仅允许收盘后120秒内发现的信号进入实时通知；超时信号仍保存，标记EXPIRED，不伪装成即时提醒。
    
- 允许通过配置开启“历史补发摘要”，默认关闭。
    
- 保存信号收盘时间、发现时间和发送时间，显示实际延迟。
    

提醒至少包含：

- 交易对、合约类型、周期。
    
- K线开盘时间和收盘边界，北京时间。
    
- 收盘价。
    
- EMA12、EMA50、EMA200。
    
- “EMA12 > EMA50 > EMA200：满足”。
    
- 基础币成交量、USDT成交额。
    
- 前20根均量、最大量和量比。
    
- 阳线实体、相对实体倍数。
    
- 开收盘涨幅和此前最大涨幅。
    
- 突破前20根最高价的幅度。
    
- 实体占比、上影占比。
    
- 数据状态、策略版本和signal_id。
    
- 提醒类型：监控条件触发，不代表实际交易。
    

默认提供控制台提醒及本地事件日志。外部渠道采用可插拔适配器，只有明确配置并获授权后才发送；不擅自向任何联系人或群组发消息。

通知失败时有限重试，记录状态。通知模块故障不能阻塞行情接收及信号落库。说明外部通知渠道可能不支持严格“恰好一次”投递，并利用稳定事件ID控制和识别重复。

九、Excel：四个周期分别保存

必须生成四个独立工作簿：

- 币安USDT合约监控_15分钟.xlsx
    
- 币安USDT合约监控_1小时.xlsx
    
- 币安USDT合约监控_4小时.xlsx
    
- 币安USDT合约监控_日线.xlsx
    

禁止把四个周期混在同一个工作簿中代替上述要求。

每个工作簿包含以下工作表：

1. 监控概览
    

每个交易对一行，展示该周期最新已收盘K线的：

交易对、合约类型、收盘时间、收盘价、EMA12/50/200、多头排列状态、量比、相对实体倍数、涨幅、六项条件结果、整体触发状态、数据准备状态、最后更新时间。

必须覆盖该周期全部应监控标的，不能只列触发者。

2. 触发记录
    

保存全部正式触发及启用的历史分析记录，包括：

signal_id、策略版本、交易对、合约类型、周期、开收盘时间、UTC毫秒、OHLC、基础币成交量、USDT成交额、EMA12/50/200、各比较指标、六项条件结果、事件类型、发现时间、通知状态和延迟。

3. 前20根对照
    

对每个触发事件保存此前20根K线的逐条数据，以signal_id关联：

序号、开收盘时间、OHLC、基础币成交量、USDT成交额、绝对实体、相对实体、开收盘涨幅、对上根收盘涨幅。

目标K线不混入这20根。

4. 数据状态与异常
    

保存预热不足、缺失K线、补数、订阅异常、交易对上下线、导出失败等记录。

5. 参数与说明
    

保存策略版本、阈值、指标公式、时间规则、数据来源、生成时间及字段单位。

Excel工程要求：

- 价格、数量、百分比和时间使用正确的数据类型及格式。
    
- 不把所有价格固定为两位小数；根据交易对精度合理展示。
    
- 冻结表头，支持筛选，列宽合理，长文本自动换行。
    
- 不使用宏或外部链接。
    
- 明确展示历史记录与实时提醒的区别。
    
- 没有触发时仍生成工作簿和完整监控概览，不伪造信号。
    
- 默认按可配置周期批量刷新，例如每60秒一次，不随每个行情事件反复写整个文件。
    
- 每次导出带导出时间，便于识别快照的新鲜度。
    

以数据库作为持久化事实来源，Excel作为可重新生成的输出文件。完整历史K线保存在数据库中；默认Excel保存最新全市场快照、触发记录及其前20根明细，避免复制全市场全部历史导致文件不可用。

接近Excel行数限制或配置容量上限时，按周期、月份和分卷归档，保留历史，不能覆盖丢失旧信号。四种周期始终分开。

使用临时文件和同盘原子替换等安全方式导出。文件被Excel占用时保留原文件及待导出状态，重试或另存带时间戳的快照，不能丢失数据库数据。
